# 段落・文・セクション移動

単語より大きく、ファイルより小さい構造単位で跳ぶ。散文・コードブロック・言語認識ナビゲーションに有効。

## コマンド一覧

| Key   | 動作                                                              |
|-------|-------------------------------------------------------------------|
| `{`   | 後方の空白行（段落）境界へ                                        |
| `}`   | 前方の空白行境界へ                                                |
| `(`   | 後方の文先頭へ。文は `.` `!` `?` + 行末 or 空白/タブ で終了（句読点と末尾空白の間に `)` `]` `"` `'` が任意個入ってもよい）。**段落・セクション境界も文境界として扱われる** |
| `)`   | 前方の文先頭へ                                                    |
| `[[`  | 後方へ `[count]` **セクション**、または列 0 の前の `{` へ（セクションは `'sections'` と列 0 の form-feed (CTRL-L) で定義） |
| `]]`  | 前方へ `[count]` セクション、または列 0 の次の `{` へ              |
| `][`  | 前方の列 0 の `}` へ                                              |
| `[]`  | 後方の列 0 の `}` へ                                              |
| `[m`  | 後方の**メソッド**先頭へ — Java 系言語向けに設計、`{`/`}` のネストを追跡してクラスメンバ境界を探す |
| `]m`  | 前方のメソッド先頭へ                                              |
| `[M`  | 後方のメソッド末尾へ                                              |
| `]M`  | 前方のメソッド末尾へ                                              |
| `[*` (`[/`) | 後方の **C** コメント（`/* ... */`）の先頭へ                |
| `]*` (`]/`) | 前方の C コメントの末尾へ                                    |

## 使い分け

- **`{`/`}` vs `(`/`)`**: 段落（空白行区切り） vs 文（ピリオド区切り）。コードでは `{`/`}` がほぼ常に正解、`(`/`)` は散文編集向け
- **`{`/`}` vs `ip`/`ap`**: `{`/`}` は **motion**（カーソル移動）、`ip`/`ap` は **text object**（領域選択）。移動には motion、操作にはオブジェクト（`dap` で段落削除）
- **`[[`/`]]` vs `]m`/`[m`**: `[[`/`]]` は**列 0** の `{` 依存（C/C++/Java の伝統的スタイル）。`]m`/`[m` は `{`/`}` のネストを追跡してクラスメンバ境界を探す（Java 系）。インデント付きで `{` が列 0 にない現代コードでは `]m` の方が信頼できる
- **`}` vs `G`**: `}` は次の空白行まで — コードをチャンク読みするのに便利。`G` はファイル末尾。`}` 連打で chunk スクロール
- **`(`/`)` vs `f.`**: 文ナビゲーションは `)` の方が賢い（`!` `?` 対応、略語スキップ）が、`f.;` の方が単純なピリオド跳びには速い

## 文法での位置づけ

全 operator と合成可:

- `d}`   — 次の空白行まで削除（段落 forward）
- `c}`   — 段落を置換
- `y}`   — 段落をヤンク
- `dap`  — 段落と末尾空白行を削除（text object 形式）
- `=ap`  — 段落を自動整形

## 実例

```text
function foo() {        }      → 次の空白行へ
  x = 1;
                                段落境界（空白行）
  y = 2;
}

コード斜め読み:        ] ] ] ]    トップレベル関数定義を辿る
文を前方削除:          d)         現在の文末まで削除
ブロック整形:          =ap        現段落を自動整形
```

## 落とし穴

- 「文」はデフォルトで `.`/`!`/`?` の後に**行末か空白/タブ 1 つ**が必要。段落・セクション境界も文境界扱い。`'cpoptions'` に `J` フラグを追加すると**空白 2 つ**を要求し、かつ**タブはもう区切りとして認識されない**
- `[[` は列 0 の `{` を要求。インデント中括弧（現代の formatter のほとんど）では機能しない。`]m` または text object を使う
- `[m`/`]m` は **Java/C++ などメソッドを `{` `}` で区切る言語**向け設計。filetype 次第で、Python/Ruby は信頼性低（言語別プラグインを使う）
- 段落・セクション境界は `'paragraphs'` `'sections'`（nroff マクロペア、`.IP` `.LP` `.SH` 等）の影響も受ける。既定は nroff 文書向けで現代では稀にしか変更しないが、非コードファイルで `{`/`}` や `[[`/`]]` の挙動が予想と違う時はこれらを確認
